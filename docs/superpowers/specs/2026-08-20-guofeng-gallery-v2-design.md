# Codex 国风主题馆与五套新主题 v2 设计规格

## 目标

在现有 Windows v1.6.0 国风发行版上新增五套已确认的原创主题，并建立一个可由 GitHub Pages 托管的公开“Codex 国风主题馆”。主题馆负责展示、筛选、预览、下载和引导安装；Windows 客户端继续负责受限导入、一键切换、失败回滚和恢复官方外观。

本轮预定版本为 v1.7.0，完成后内置主题总数从 3 套增加到 8 套：竹青、朱砂、墨韵、汝窑天青、敦煌鎏金、青花瓷、海棠宋锦、霁夜星河。

## 上游兼容审计

### 当前基线

- 上游：`Fei-Away/Codex-Dream-Skin@95423d849f74b9824db2ba0c1121cc7a13b56d10`，正式版 v1.5.14。
- 本项目 `origin/main@7e4c24833f81262c6882d0a21c5d56dfa311e596` 是该上游提交的直接后继，只增加国风品牌、三套主题和 Windows-only 发布流程。
- 2026-08-20 审计时，上游 `main` 没有比本项目基线更新的客户端提交，因此本轮不需要补拉遗漏提交。

### 必须保留的上游修复

本轮不得改弱或绕过以下机制：

- Codex 26.721 / 26.727 DOM 与设置页选择器兼容。
- 慢启动 90 秒验证、可见渲染器判断和“不误杀已正常显示窗口”。
- 启动失败外观 journal、三方恢复、last-known-good 和活动主题原子提交。
- 官方 Store 包、进程、CDP Browser ID、回环端点和精确路径身份验证。
- 自带 Node.js 的签名、发布者、哈希、Unicode 路径和“验签先于执行”。
- ZIP 条目数、压缩/解压大小、路径穿越、链接、媒体魔数、像素、SHA-256 和 Safe CSS 校验。
- 一键换肤冷启动、已验证旧主题基线、失败回滚和不强杀仍运行的子进程。
- 配置文件 UTF-8、TOML 结构、并发写与 appearance 回滚保护。

### 后续同步策略

比较过三种策略：

1. 冻结当前分叉：开发最快，但会遗漏安全和 Codex DOM 兼容修复，不采用。
2. 随上游整仓覆盖：容易冲掉国风目录、品牌和 Windows-only 发布逻辑，不采用。
3. **以 `upstream/main` 为核心基线、国风功能保持数据层增量，并为冲突点设置回归门禁：采用。**

以后每次同步从专用分支合并新的 `upstream/main`，优先保留上游核心脚本和共享 runtime；只在主题清单、主题素材、展示品牌、Windows 构建清单和网页目录解决冲突。安全或兼容修复不得只摘一部分；合并后必须跑完整 Windows 测试和安装器构建。

## 产品范围

### 本期包含

- 五套新主题的纯背景、`theme.json`、Safe CSS 和 Gallery 预览。
- Windows 托盘中的 8 套内置主题一键切换。
- GitHub Pages 静态站点：主题卡片、搜索、明暗筛选、主题详情、下载、安装说明、GitHub Star 入口。
- 主题列表由一份站点数据文件驱动，避免手工复制卡片。
- 桌面、平板和手机响应式布局；键盘导航、焦点态和减少动效支持。
- 主题 ZIP 作为 Release 附件或站点下载入口；客户端下载仍指向 GitHub Release。
- README、Windows 文档、更新日志和预览素材更新。

### 本期不包含

- 账号、登录、评论、收藏、排行榜、投稿审核、数据库或服务端 API。
- 冒充 DreamSkin.cc 的社区数量、热度或作者数据。
- macOS 客户端、DMG 或 macOS 实机兼容声明。
- 修改官方 Codex 文件、签名、WindowsApps 权限或 `app.asar`。
- 绕过 SmartScreen、Defender、执行策略或主题安全校验。

## 五套新主题

### 汝窑天青 `preset-ruyao-tianqing`

- 浅色主题，雨过天青、釉面开片、温润灰青。
- 纯背景保持中央与左侧安全留白，开片纹理只作低对比装饰。
- 面板为半透明釉白，强调色用克制的青灰绿。

### 敦煌鎏金 `preset-dunhuang-liujin`

- 深色主题，石窟赭褐、矿物蓝绿、少量哑金。
- 使用藻井、飞天飘带和壁画边饰的抽象构成，不直接复制文物图像。
- 金色仅用于边线与按钮强调，正文保持高对比暖白。

### 青花瓷 `preset-qinghua-ci`

- 浅色主题，瓷白基底、雾蓝灰侧栏、青花纹样和一件明确瓷器主体。
- 避免整屏高饱和蓝；纹样集中在右侧和边缘，工作区保持安静。
- 侧栏比初稿更浅，正文使用深墨蓝而非纯黑。

### 海棠宋锦 `preset-haitang-songjin`

- 浅色主题，米绢底、海棠纹、宋锦织造的经纬和边框层次。
- 纹样比普通花卉壁纸更有织物结构，避免只剩素色纸面。
- 强调色使用海棠红、茶褐和低饱和金棕。

### 霁夜星河 `preset-jiye-xinghe`

- 深色主题，中国传统星官图、黛蓝夜空、金线星轨与山形剪影。
- 属于“古代天文审美”的中国风，不做现代霓虹宇宙或游戏 HUD。
- 面板使用半透明黛蓝，金色只作为星点和焦点强调。

## 主题馆信息架构

### 页面骨架

借鉴 DreamSkin Gallery 的成熟浏览逻辑，但采用独立国风视觉：

1. 顶部导航：品牌、主题馆、安装、制作主题、GitHub。
2. 首屏：大标题“为你的 Codex 换一袭东方颜色”、简短说明、安装和 GitHub 按钮。
3. 分类条：全部 / 浅色 / 深色；搜索框按中文名、拼音名和标签过滤。
4. 主题网格：8 张真实 Codex 小窗口预览卡，显示名称、风格标签、明暗属性和主要操作。
5. 详情弹层：大预览、设计说明、色板、兼容版本、下载 ZIP、查看文件。
6. 安装说明：安装客户端、下载或内置选择、一键恢复三步流程。
7. 页脚：非官方声明、MIT、上游致谢、隐私和安全边界。

### 视觉系统

- 背景：暖宣纸白，辅以极淡纸纤维噪点；不铺满仿古纹理。
- 文字：标题使用系统可用的中文宋体/衬线回退，正文使用现代无衬线，保证跨平台稳定。
- 强调：竹青为主交互色，朱砂用于印章、徽记和极少数焦点，不把页面做成春节风。
- 卡片：像装裱册页而不是电商卡片；细墨线、轻投影、圆角克制。
- 动效：卡片悬停轻抬、预览渐显、详情淡入；尊重 `prefers-reduced-motion`。
- 移动端：筛选可横向滚动，卡片单列，详情变为整页抽屉，所有按钮至少 44px。

### 与原版 Gallery 的区别

- 原版面向大型社区，包含投稿、作者、热门、收藏、分页；本项目首版是精选主题馆，不伪造社区数据。
- 原版以黑白现代主义为主；本项目使用宣纸、宋式排版、竹青和朱砂印记。
- 原版的一键换肤依赖 DreamSkin.cc 服务；本项目优先展示内置主题和 GitHub Release 下载，只有明确兼容时才提供协议按钮。

## 站点实现

### 技术选型

采用 Product Design 的 Vite/React 静态模板，放在 `site/`：

- 以用户选中的“东方数字展馆”视觉稿为唯一实现目标，不把模板默认样式带入成品。
- `site/src/data/themes.ts` 为单一展示数据源，组件只消费数据，不重复手写主题卡片。
- `site/public/assets/` 保存站点标识、宣纸竹影装饰和 8 套主题预览。
- 站点只做前端交互，不引入账号、数据库或服务端业务；生产构建仍可作为纯静态 Pages 资产发布。
- `.github/workflows/pages.yml` 用 GitHub 官方 Pages Actions 部署构建结果，Actions 固定完整 commit SHA、最小权限。
- 自动测试校验数据、链接、资源、核心交互、可访问性关键属性和站点构建；本地浏览器完成桌面与移动视觉验收。

### 主题下载

- 内置主题无需重复下载，详情按钮显示“客户端内置 / 打开安装说明”。
- 同时为每套主题构建普通 `.zip`，严格包含 `background.jpg`、`theme.json`、`theme.css`，供现有用户单独导入。
- 站点链接使用版本化 GitHub Release URL，避免 Pages 缓存旧包。
- 在 Release 尚未发布前，站点明确显示“随 v1.7.0 发布”，不放失效的假下载按钮。

## 数据和兼容改动

- `windows/presets/catalog.json` 扩展为 8 个有序 ID，竹青仍是默认主题。
- `Read-DreamSkinBundledPresetCatalog` 不再硬编码“三套”，改为有界的 `1..32` 套，并继续拒绝空、重复或非法 ID。
- Windows 引擎和安装器的 required-file 清单从数据清单派生或由测试锁定 8 套三件套。
- 构建器继续对所有审核主题文件做 SHA-256 固定校验；新增素材后必须更新审核哈希。
- 不修改主题 schema、Safe CSS 策略、共享 renderer、CDP 协议和状态目录。

## 测试策略

严格测试先行：

1. 先把主题目录测试改为期待 8 套，确认在只有 3 套时失败。
2. 增加 Catalog 上界、重复 ID、缺件、额外文件、非法 CSS 的失败测试。
3. 增加五套主题 JSON、图片尺寸/魔数、Safe CSS、色彩完整性和 ZIP 内容测试。
4. 增加站点测试：8 张卡、筛选标签、详情数据、资源存在、下载链接版本一致、基础 ARIA 和无障碍焦点。
5. 实现后运行完整 `windows/tests/run-tests.ps1`，使用 Codex bundled Node，不要求系统全局安装 Node。
6. 构建 Setup.exe 并静态核对 8 套主题；若可用，完成真实 Codex 切换和恢复 smoke test。
7. 本地启动静态站点，使用桌面与移动视口截图验收，无横向溢出、无 404、无控制台错误。

## 失败与恢复

- 新主题有任一缺件、哈希不符、CSS 非法或图片超限时，初始化/构建 fail closed。
- 增加主题不得切换已有用户的活动主题；仅全新安装默认竹青。
- 同 ID 主题升级继续原地刷新审核预设，但不得覆盖用户自建的不同 ID。
- Gallery 加载失败时保留可阅读的静态标题、安装链接和主题名称；JavaScript 只增强筛选和详情。
- Pages 部署失败不影响客户端 Release，客户端发布失败也不得让站点提前宣称可下载。

## 完成标准

- 8 套主题在客户端目录、安装器、测试、文档和站点数据中一致。
- 五套新主题具有纯背景和 Gallery 预览，不使用带 UI 的预览图作为运行时背景。
- 完整 Windows 回归、站点测试、安装器构建与静态站点验收通过。
- 对外清楚区分：本地完成、已测试、已提交、已推送、Pages 已部署、Release 已发布。
- 提交、推送、PR、合并、Pages 设置和 v1.7.0 Release 按 GitHub 操作边界分别执行；发布后再核对公开页面、资产和 SHA-256。
