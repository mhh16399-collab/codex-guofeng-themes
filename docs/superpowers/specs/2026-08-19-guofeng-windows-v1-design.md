# Codex 国风主题工坊 Windows v1 设计规格

## 目标

在 `Codex-Dream-Skin` 的可恢复 Windows 换肤内核上，交付一个具有独立视觉身份的 Windows 发行版：**Codex 国风主题工坊（Codex Guofeng Themes）**。首版内置竹青、朱砂、墨韵三套原创国风主题，首次安装默认启用竹青，用户可在现有系统托盘菜单中一键切换三套主题、导入兼容 ZIP，并随时恢复官方 Codex 外观。

本版本的成功标准不是“把界面染成三种颜色”，而是让三套主题在同一套原生 Codex 信息架构上形成清晰、可辨认且适合长时间工作的视觉系统，同时保留上游已经验证过的安全、回滚和安装能力。

## 范围

### 本期包含

- 仅支持 Windows 10/11 x64，保留官方 Microsoft Store `OpenAI.Codex` 身份校验。
- 三套内置主题：
  - `preset-zhuqing`：竹青，纸白、竹影、青绿色，清爽安静。
  - `preset-zhusha`：朱砂，暖瓷白、宫墙朱红、月洞与窗棂投影，克制而非节庆。
  - `preset-moyun`：墨韵，冷宣纸、山水、飞白墨迹，不出现竹叶或植物意象。
- 首次安装默认启用竹青；已有安装的活动主题和自定义主题不得被覆盖。
- 三套主题均出现在 Windows 托盘“已保存主题”中，可直接切换。
- Windows 用户可见品牌改为“Codex 国风主题工坊 / Codex Guofeng Themes”。
- 中文优先、英文可用的根 README、Windows README、安装器和托盘文案。
- 保留兼容的主题 ZIP 导入、DreamSkin.cc Gallery/Studio 入口和 `dreamskin://` 协议，并明确标注其为上游兼容服务。
- 提供三套实机风格预览图和清晰的安装、恢复、兼容性说明。

### 本期不包含

- macOS 发行版或 macOS 菜单栏改造。
- 自建在线主题商城、账号系统、审核后台或托管 API。
- 修改官方 Codex 的 `WindowsApps`、`app.asar`、签名、ACL 或二进制文件。
- 更换内部状态目录 `%LOCALAPPDATA%\CodexDreamSkin`、CDP 协议、主题 ZIP 合同或 `dreamskin://` URL 协议。
- 静默安装、静默换肤、关闭 Defender/SmartScreen 或绕过 PowerShell 执行策略。

## 关键取舍

### 复用内核，分离展示品牌

保留 `DreamSkin` 内部函数名、状态路径、配置键和协议名称，避免破坏上游更新兼容性及用户恢复能力。只修改用户可见标题、说明、图标旁文案、安装器产品名和仓库文档。README 必须明确声明本项目基于 `Fei-Away/Codex-Dream-Skin`，保留 MIT 许可和原作者归属。

### Windows 独立增量，不制造双端漂移

本期不改 `runtime/` 共享 renderer、安全 CSS 策略或主题包 schema。视觉差异全部通过 Windows 主题 JSON、纯背景图和通过现有 Safe CSS 校验的 `theme.css` 完成。因此无需修改 macOS 运行时副本，也不会声称 macOS 已支持。

### 主题素材与 UI 分离

预览图用于展示，不可作为运行时背景。每套主题必须拥有独立的 16:9 纯背景图，图中不得含 Codex 窗口、侧栏、按钮、输入框、文字或 Logo。原生 UI 继续由 Codex 渲染，主题只提供背景、颜色变量和允许范围内的组件样式。

## 视觉系统

### 竹青

- 基底：柔和纸白，不使用纯白高亮。
- 主色：竹青、深松绿、浅玉色。
- 图像：右侧和右下角淡竹影，中心与左侧保留大量安全留白。
- 组件：浅青半透明面板、细绿灰边框、深绿色发送按钮。
- 气质：清透、自然、适合白天长时间工作。

### 朱砂

- 基底：暖瓷白与浅陶土色。
- 主色：深朱砂、暗漆红、少量黏土色；不使用闪亮金色。
- 图像：右侧抽象月洞门、宫墙弧线和窗棂投影；禁止祥云、水彩泼洒、灯笼、金币和春节元素。
- 组件：瓷白面板、细暖灰边框、朱红小面积强调和发送按钮。
- 气质：建筑感、秩序感、现代博物馆式国风。

### 墨韵

- 基底：偏冷宣纸白。
- 主色：墨黑、烟灰、雾蓝灰、少量黛青。
- 图像：右侧远山、江面与横向飞白笔触；禁止竹子、树枝、花叶等植物轮廓。
- 组件：冷纸色面板、石墨细边框、极轻阴影、墨黛色发送按钮。
- 气质：山水留白、安静克制，与竹青有明显题材差异。

### 可用性约束

- 正文对比度目标不低于 WCAG AA；装饰图层不得影响文字可读性。
- 装饰层必须 `pointer-events: none`，真实导航、项目按钮和输入框保持可交互。
- 首页允许更强氛围，任务页使用现有 `ambient` 逻辑降低背景干扰。
- 主题在 1366×768、1440×900、1920×1080 和高 DPI 下不得产生横向溢出。

## 主题包结构

每套内置主题采用与导入主题一致的三件套：

```text
preset-<id>/
  background.jpg
  theme.json
  theme.css
```

`theme.json` 必须包含唯一 `id`、中英文可识别名称、`appearance: "light"`、焦点位置、安全区域、任务模式和完整颜色集合。`theme.css` 只能使用 `runtime/safe-css-policy.json` 登记的 `data-ds-part`、状态、变量和属性，并在安装、切换和测试时通过同一个 validator。

Windows `assets/theme.json` 与 `assets/dream-reference.jpg` 保持为竹青默认主题的兼容入口；朱砂与墨韵放入 `windows/presets/`。初始化逻辑改为数据驱动的内置预设清单，避免今后每增加一套主题都复制一段 PowerShell。清单只列出发行版主动展示的主题，未列出的上游兼容素材不会自动出现在托盘中。

## 数据流

1. 安装器验证官方 Codex、固定 Node 运行时和完整运行时文件清单。
2. `Initialize-DreamSkinThemeStore` 创建受管目录并读取内置预设清单。
3. 全新状态目录从竹青兼容入口写入 `active/`，随后把竹青、朱砂、墨韵写入 `themes/`。
4. 已存在 `active/theme.json` 时不切换活动主题，只刷新同 ID 的内置预设副本和安全元数据。
5. 用户从托盘选择主题后，现有 `Use-DreamSkinSavedTheme` 重新校验图片、JSON 和 Safe CSS，再原子写入活动主题。
6. renderer 通过现有 CDP 注入读取活动主题，验证可见性；失败时继续使用现有回滚流程。

## 错误与恢复

- 任一内置主题缺少 JSON、CSS 或唯一背景图时，安装/初始化必须失败并指出相对路径。
- 预设 ID 与目录不一致、重复 ID、图片超限、Safe CSS 不合法时 fail closed。
- 新安装默认主题失败时不得留下半写入活动主题。
- 升级时不得覆盖用户正在使用的自定义主题、已导入主题或较新的外观配置。
- 启动或渲染验证失败时沿用上游精确进程身份、配置三方比较和 last-known-good 回滚。
- 完整恢复继续关闭调试会话并重新启动官方 Codex，不删除用户保存的主题和图片。

## 测试与验收

### 自动测试

- TDD 更新 Windows 主题初始化断言：全新状态默认竹青，托盘可发现且仅主动预置竹青、朱砂、墨韵。
- 验证三套主题目录/兼容入口的 ID、图片名、`appearance`、安全区和题材元数据。
- 验证每套 `theme.css` 通过共享 Safe CSS validator，恶意选择器或未知属性仍被拒绝。
- 验证二次初始化不覆盖自定义活动主题，不重复保存主题。
- 验证安装器和托管运行时文件清单包含三套主题所需文件。
- 运行 `windows/tests/run-tests.ps1`、相关 Node 语法检查、PowerShell 5.1 静态兼容检查及 `git diff --check`。

### 视觉验收

- 为三套主题各生成一张纯背景和一张 1584×1024 预览。
- 预览必须清晰显示同一 Codex 布局下的三种不同视觉语言。
- 若当前官方 Codex 版本能开放经过验证的本机 CDP 端点，分别完成首页、普通任务页、输入框、项目选择和托盘切换 smoke test。
- 若上游 Codex 版本阻止 CDP，则如实记录“真实注入受上游阻塞”，不得用模拟预览冒充实机验证。
